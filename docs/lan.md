# 同一 Wi‑Fi：HTTPS 配对

LAN 与 USB 是两个独立入口。USB 继续只监听回环地址；LAN 手动启用，只在指定的本机私有 IPv4 地址上监听 TLS，并拒绝非私有 IPv4 来源、错误 Host 和带 Origin 的请求。不用于公网或端口映射。

1. 用 `pi install /Users/alex/zmh/repo/pi-go` 安装扩展，打开或重载 Desktop 会话。运行 `/pi-go-lan <本机私有 IPv4> 18981`；电脑需有支持 `-addext` 的 OpenSSL 在 PATH 中。
2. 在电脑本地打开通知所指的 `pair.json`，把 `bundle` 的值通过可信渠道交给自己的手机。也可执行 `swift scripts/pair-qr.swift /path/to/pair.json`，本地打开返回路径的二维码。二维码和配对文件会一同过期或在兑票后删除。不要上传、转发或扫描来源不明的配对包。
3. 手机与电脑使用同一 Wi‑Fi。在 Pi Go 切到「局域网」，可点「发现电脑」查看附近地址；这是 UDP 18976 的未验证提示，不会发起连接。点「扫码导入」或手动粘贴配对包，再点「配对并连接」。包包含地址、证书、公钥指纹与两分钟单次票据；LAN 不接受 USB 八位短码。手机验证 TLS 证书和公钥指纹后才发送票据。连接后，证书、指纹和设备凭证随 HUKS 加密保存。若路由器屏蔽广播，扫码和粘贴仍可使用。
4. 在更多标签执行 `/pi-go-share`。在适配版 Desktop 中，可选用 `/pi-go-project 18981` 保留无共享标签时的项目访问。
5. `/pi-go-revoke-device 18981` 撤销手机凭证和未使用的票据，保留监听。用 `/pi-go-bridge-stop 18981` 关闭监听。每个入口只保留一个活跃配对；新配对成功即替换旧凭证。

退出并重启手机 App 可在原桥仍运行时重连。桥重启时重新生成证书与密钥并清除配对；电脑 IP 变更后须停旧桥，按新 IP 启动并重新配对。

## 真机验收

鸿蒙真机在没有 LAN 端口 USB 转发的情况下，拒绝了错误公钥指纹，接受正确配对包。强制停止再启动 App 后自动恢复配对，能发送消息并收到离线模型回复。桌面撤销后，手机回到配对页并显示撤销提示。

真机也通过 UDP 广播发现了电脑，显示为未验证地址，并能打开系统二维码扫描界面。Mac 端的二维码解码已验证与原始配对包逐字一致；用真机相机扫描桌面二维码并完成配对的整条路径尚未验收。

## 多电脑

在聊天页点「电脑」返回配对列表，这不会删除凭证。可再配对一个 LAN 或 USB 地址，或从列表切换。同一地址重新配对时替换该条记录；USB 上的不同电脑应使用不同的反向转发端口。手机最多保留 12 条记录，重启时恢复上次连接的地址；如果上次停在列表，就不主动连接。旧版单条配对可直接读取。

列表「移除」只删除所选电脑在手机上的凭证。要吊销凭证，请在该电脑执行桌面撤销命令。某台电脑返回撤销后，手机移除该条记录，不影响其他电脑。草稿按电脑和会话分别留在当前 App 进程内，不持久化。

真机用两条 USB 转发连接两个隔离的 Desktop 实例：切换后未见前一实例草稿，切回后草稿恢复；强制停止再启动 App 后恢复上次选中的实例。一条凭证被换发作废后，手机只移除了该记录，另一实例无需重新配对。
