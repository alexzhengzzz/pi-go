# 阶段 0：Pi Desktop 兼容性验证

## Pi Desktop 手工验收

1. 使用两个新建的废弃项目。确认 Desktop 选用与上表相同的 Pi 引擎；不要在现有重要会话上运行探针。用 `pi install -l /Users/alex/zmh/repo/pi-go` 在两个测试项目本地安装，Desktop 信任该项目后重新打开会话。若项目级包未被发现，先检查 Desktop 的实际引擎路径、项目 cwd 和信任状态。
2. 每个项目先通过 Desktop 保存至少一轮消息，第一个项目再建一个会话。确认切换目标未在任何其他标签或进程打开。本阶段**没有跨进程会话锁**，不要用同一文件做双写测试。
3. 按 [USB 联调](usb.md) 配对，分别共享两个原生标签。在手机选择并分别发送不同短消息；核对 Desktop 标签原路径、对话和原生 JSONL。关闭手机选中的标签；确认手机提示关闭，旧写操作不会落到另一个标签。
4. 在 Desktop 运行 `/pi-go-check-ui`，分别验证确认和取消。后续补验关闭最后一个标签、退出和重启 Desktop、强制结束，以及同一会话重复占用的界面反馈。
5. 运行 `/pi-go-bridge-stop` 撤销凭证并关闭监听。每个测试项目运行 `pi remove -l /Users/alex/zmh/repo/pi-go` 并重新打开会话以卸载。

## 下一道门槛

共享桥不写会话 JSONL，也不启动第二套 Pi runtime。已验证原生打开与新建、无共享标签或 Desktop 进程重启后的项目恢复，以及真机扩展确认、单行输入和多行编辑。USB 继续使用回环入口；[独立 HTTPS 入口](lan.md) 已验证手动配对和 UDP 发现。整机重启和真机相机扫码配对仍待验收，暂不冻结协议。

## 阶段 2 目录增量验证（2026-11-20）

手机会话页支持按标题、项目路径和会话 ID 搜索、显示匹配总数、每页 30 条加载更多。更改搜索条件后点击“搜索”会从第一页刷新；清空搜索可恢复全部目录。追加页按会话 ID 去重，切换电脑会清空旧目录和搜索条件。目录目前使用实时偏移分页，列表变动时应重新搜索刷新。

自动验证：`npm test` 覆盖搜索命中/无结果、正常分页、末页、超出目录范围的游标、非整数页大小，以及模型切换和会话改名；`zsh scripts/build-harmony.sh` 验证 ArkTS 编译和签名 HAP 打包。测试仅使用离线模型和临时项目。

真机待验收：准备超过 30 条历史的共享项目，依次检查搜索、加载更多、清空搜索、断网后的重试、切换电脑后旧目录不残留；在加载期间从桌面关闭/新建会话后重新搜索。构建通过不代表这些交互已完成真机验收。
