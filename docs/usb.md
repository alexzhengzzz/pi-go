# 鸿蒙 USB 真机联调

这条路径只用 USB，不开放局域网端口。手机控制的是 Pi Desktop 启动的真实 Pi 进程，不是旁路 CLI、模拟聊天或独立会话库。一次配对可以访问多个显式共享的桌面标签。

## 安装及连接

1. 在 Mac 执行 `pi install /Users/alex/zmh/repo/pi-go`，然后在 Pi Desktop 打开一个测试项目并新建会话。已有运行时需要重新打开才能加载新扩展。桌面命令列表应显示 `EXTENSION pi-go`。
2. 在 DevEco Studio 打开 `/Users/alex/zmh/repo/pi-go/harmony`，为 `com.alex.pigo` 配置包含手机的调试签名。签名材料仅放在本机，不提交。
3. 从仓库执行 `/bin/zsh scripts/build-harmony.sh` 和 `/bin/zsh scripts/install-usb.sh`。脚本安装已签名 HAP，并配置 HDC 反向端口；多设备时设置 `HDC_TARGET`。默认 `18977`，如本机冲突，用 `PIGO_USB_PORT` 指定其他高端口，下一步保持一致。
4. 在 Desktop 聊天栏发送 `/pi-go-bridge 18977`。若第一个回车只是选中命令建议，仍需点发送。桌面通知只显示票据文件路径；在 Mac 本地打开该文件，把 `code` 手动输入手机。票据两分钟内有效，只能使用一次，连续输错五次即失效。旧版已配对时，先在手机断开旧连接。
5. 在其他要控制的 Desktop 标签执行 `/pi-go-share`，不必重新配对。手机的 **会话** 列表显示已共享标签与其项目的历史；未共享的历史需先在桌面打开，再执行 `/pi-go-share`。切换手机会话不会切换桌面前台标签。已选标签关闭时，手机提示会话关闭，不会把消息转到别的标签。
6. 在单个标签运行 `/pi-go-stop` 可以停止共享。在任一加载了扩展的标签运行 `/pi-go-bridge-stop 18977` 会停止整个入口并保留配对。`/pi-go-revoke-device 18977` 会使原凭证失效。手机「电脑」返回列表；「移除」会删除手机上保存的配对。USB 转发可用 `hdc fport ls` 查看。

## 运行中发送消息

Pi 正在运行时，草稿为空时输入框右侧显示「停止」，输入文字或添加附件后切换为「发送」。这时发送默认使用 Pi 的原生 `steer`，在当前工具批次结束后交给 Pi。若目标运行已结束或变更，桥接会拒收，手机会保留草稿。

运行一开始，`/events` 的 `session/status` 帧就携带 `runId`，手机立即可引导，不必等 `/chat` 轮询；排队成功后新增的 `queue/status` 帧会即时回传 `queued` 状态（旧版手机端会忽略该帧），排队消耗、会话状态仍由 `/chat` 轮询兑底纠正。会话胶囊会显示「排队中」。

如果网络断开导致发送结果未知，手机保留草稿并提供「核对发送」。请求编号可在同一个运行时核对桥是否已转发，不代表模型已经处理。运行时重启后不一定还有记录；不会自动重发。

真机在两个独立的运行中分别点击了这两个按钮；两条测试消息均写入对应的原生会话记录，各出现一次。回归测试另外覆盖了过期运行、重复请求和回执查询，以及 `session/status` 携带 `runId/queued` 与 `queue/status` 帧的新鲜性。

## 发送图片

当前模型支持图片时，手机聊天输入栏显示「图片」。从系统文件选择器选一张图，确认尺寸后可单独发送，也可附文字。客户端将图片缩放并重新编码为 JPEG（长边不超过 1280 像素，最大 512 KiB），不复制原文件元数据。附件与草稿按电脑和会话隔离，在 App 进程内暂存。

真机发送了合成测试图，原生 Pi 会话收到一张 JPEG，测试模型也确认收到了图片。聊天历史目前显示图片数量，不回传图片内容。自动化验证还覆盖错误会话、无效格式、超限、纯文本模型拒绝和请求去重。

## 从手机打开历史或新建会话

原版 Pi Desktop `0.2.2-alpha` 不提供进程外的原生会话管理接口。安装扩展已足够控制已共享的标签；要从手机打开还没运行的会话或新建标签，还需要一个启用 Pi Go 适配层的 Pi Desktop 构建。

1. 获取 Pi Desktop `v0.2.2-alpha` 的独立源码检出。在 Pi Go 仓库执行 `/bin/zsh scripts/prepare-desktop-host.sh /path/to/pi-desktop`，它只修改该源码目录，不替换 `/Applications/Pi Desktop.app`。
2. 在 Desktop 源码目录执行 `npm ci`、`npm run typecheck`、`npm run build`。以 `PIGO_DESKTOP_HOST=1 npm run preview` 启动。不要让两个桌面实例同时操作同一 GUI 配置；隔离联调时分别设置 `PI_DESKTOP_USER_DATA_DIR` 和 `PI_CODING_AGENT_DIR`，并在后者安装 Pi Go 扩展。
3. 打开一条会话并执行 `/pi-go-bridge`，然后配对。手机「会话」列表显示该项目的「新建」入口；点未运行的历史会话也能直接从 Desktop 打开。两种操作都由 Desktop 创建或恢复自己的标签，执行权限沿用它的设置，不替换桌面当前标签。

适配层只通过当前用户私有的 Unix socket 接收请求；手机不能指定历史文件或任意工作目录。Pi Go 授权、打开历史或新建会话时，会自动登记工作区并保存信任状态，无需在 Desktop 中手动信任。已登记的项目会出现在电脑配对的项目列表中。

如果希望最后一个共享标签关闭后仍能从手机打开该项目，在 Desktop 对应会话执行 `/pi-go-project`（自定义端口时带端口参数）。这会在当前 USB 桥的生命周期内授权该项目，绑定当前 Desktop 用户配置与 Pi 数据目录。关闭标签后，由手机显式选择要打开的会话。用 `/pi-go-project-stop` 撤回这项授权；仍打开的显式共享标签不受它影响。Mac 重启后需重新启桥并授权项目；使用原端口和 Pi 数据目录启动时，手机可以沿用配对。

## 2026-11-20 实测

- 启用适配层后，当前共享会话的确认、选择、单行输入和多行编辑请求显示在手机聊天页。手机与 Desktop 共用一个待应答队列，先提交的有效应答生效。真机往返验证了确认、输入、以及编辑器预填、空格和换行。手机文本答复上限为 1024 个 UTF-16 代码单元；超限预填不截断，改由 Desktop 应答。输入和编辑器草稿只存在手机页面内存，未自动保存或重发。
- 真机验证 Desktop 原生工具权限：隔离工作区采用 `ask-commands`，离线测试模型请求运行一个只创建测试文件的命令。等待审批和手机拒绝后均未生成文件；再次请求并在手机确认后，文件由 Pi 的原生工具创建，内容与预期一致。

- DevEco 构建、`com.alex.pigo` 签名安装、USB HDC 反向端口和前台启动均有设备回执；不覆盖手机上的 DSH Go。
- Pi Desktop `0.2.2-alpha` 显示并执行 Pi Go 扩展命令，响应进程为 Desktop 子进程。已在手机看到「已连接」，并在手机和桌面同时看到真实回复。
- 从手机开始独立测试回合并点击「停止」，Pi 原生会话记录的 `stopReason` 为 `aborted`，手机恢复为「已连接 · 空闲」。
- 重新安装签名版后用八位码配对；通过 `hdc shell aa force-stop` 停止手机进程并重新启动后，手机从 HUKS 加密凭证自动恢复连接，不需要再次输入配对码。
- 直接在运行时切换历史，曾使桥返回目标历史而 Desktop 仍显示旧路径；USB 入口改为路由到已共享标签，不替换标签的运行时。真机通过一次配对，在两个标签分别发送 `What is 8 plus 17?` 和 `What is 7 times 9?`；手机、对应 Desktop 标签与原生会话记录一致，回复分别为 `25` 和 `63`，两条消息没有串线。升级安装后也自动恢复了新桥的配对凭证。
- 在独立 Desktop 配置中，鸿蒙真机通过 USB 直接打开未运行的历史记录「Historical session opened from the Harmony phone.」，并新建一个会话。两者均在 Desktop 标签栏显示独立的原生会话路径，进程也确认为 Desktop 的子进程。
- 真实 Desktop 进程集成测试覆盖无共享标签时的历史目录、Desktop 停止及以同一配置重启，以及用同一配对凭证打开原生历史。双运行时回归测试还覆盖项目授权撤回、不同 Desktop 配置拒绝复用授权、旧会话 ID 拒写和定向停止。
- 这次重启流程由 Mac 脚本验证，未在手机重复执行。整机重启、局域网及 `PLAN.md` 其余功能仍待实现或验收。

## 会话设置与更早消息（开发中）

点击手机聊天页顶部的“Pi Go ▾”打开会话设置，可以编辑当前会话名称；通过“模型”和“思考级别”下拉框选择后，点击“应用模型与思考级别”生效。模型列表包含桌面已配置的全部可用模型（当前设置了模型范围时遵循该范围），不再截断前 100 项。运行或队列未结束时禁止切换模型；实际生效值以桌面回执为准。若现有扩展/桥尚未重载新版，操作可能失败，不能仅凭手机安装成功认定功能可用。

长会话提供“更早的消息”，每次最多读取 60 条，以原生消息 ID 为分页边界；轮询保留已加载的旧消息。会话或分支变化导致边界失效时拒绝旧请求，重新打开会话获取基线。暂仍沿用每条消息文本最多 8000 字符的预览限制。

2026-11-20：新版手机 HAP 构建和覆盖安装成功，保留凭证后自动连接原 USB 地址，真机聊天页已出现“设置”。设置页操作及历史翻页仍需在重载新版桌面扩展/桥后验收，尚未记录为真机通过。

## 会话列表标记

会话页提供“全部 / 置顶 / 最近 / 已归档”筛选，以及每行的置顶、归档与恢复操作。“全部”隐藏已归档项；归档不删除会话、不中断运行，已归档会话可从“已归档”继续打开。“最近”记录通过该桥选中的会话，包含唯一运行时自动选中。

标记存储在电脑 `~/.pi-go/sessions-<端口>/`，目录权限 0700、文件权限 0600，按项目路径和会话 ID 的摘要隔离。与同一端口桥的重启无关；不同端口分别维护标记。测试可用 `PIGO_STATE_DIR` 指定隔离目录；设置 `PIGO_IPC_DIR` 时默认在其 `state` 子目录保存。每次更新携带版本号，旧页面修改会收到冲突，需要刷新重试。不修改原生 JSONL。当前目录仍限于最近 250 条可见目录记录，稳定快照分页待完善。

标记持久化、项目隔离、过期版本拒绝及权限通过自动测试；共享桥集成覆盖标记接口、归档恢复和未共享目标拒绝。真机列表标记操作待重载新版桥后验收。

## 工作区文件（开发中）

聊天页“工作区文件”可浏览当前共享会话的项目，分页列出目录（每页 100 项）、打开 UTF-8 文本并编辑保存。文本上限 64 KiB；硬链接或其他用户所有的文件不可保存。当前只编辑已有文件，尚不支持新建、删除。

### 电脑→手机：发文件并点击打开

任意工作区文件（含二进制，单个 ≤ 64 MiB）可通过 `GET /files/download?cwd=&path=` 原样下发到手机：鉴权、cwd 范围、拒绝绝对路径/`..`/符号链接的规则与文本接口完全一致，响应为 `application/octet-stream`。手机端三个入口都会触发“接收 → 存沙箱 → 系统预览打开”：

- 工作区文件浏览：点击常规文本进入编辑器，可用「预览」在应用内查看，预览也会显示尚未保存的修改。其他文件下载后按类型预览。
- 聊天消息：回复中的带扩展名文件路径会渲染成文件卡片（每条最多 4 张）。只给文件名时，先检查根目录，再在工作区内查找唯一匹配。工作区过大或有多个匹配时，需提供完整相对路径。带空格的路径用反引号或 Markdown 链接标记。
- 工具详情：打开已完成的 `write`/`edit`/`read` 工具活动，若文件路径位于当前工作区，点击文件卡片即可接收并打开。

文件分块写入手机应用沙箱 `cache/pigo-files/`。下载成功且字节数与响应一致后，才替换同一电脑和路径的缓存。接收时会清理超过 7 天的旧文件。Markdown、纯文本、日志、CSV、JSON 和常见源码等 UTF-8 文件可在应用内滚动查看，大文本可翻页。图片、PDF、音视频、Office 和 HTML 交给系统预览，实际支持情况由 `filePreview.canPreview` 判定。「保存到本机」通过系统文件选择器导出完整文件，适用于系统无法预览的格式。

修改保存携带原始内容 SHA-256 版本；检测到电脑修改时返回冲突，不覆盖该内容。电脑端在同目录写临时文件、同步落盘、再次检查原文件版本与 inode 后原子替换，并保留权限位。它不是与其他编辑器协同的文件锁：最终检查与 rename 之间仍有文件系统竞态窗口，后续需完善协同写入边界。手机不会自动重发超时保存，未保存时会阻止离开编辑页，用户可明确放弃修改。

文件接口仅接受当前显式共享或项目授权中的 cwd；客户端不能用文件接口增加授权。路径必须是项目内相对路径，拒绝绝对路径、`..`、符号链接和规范化后超出根目录的路径。自动测试覆盖作用域、大小/类型、目录分页、保存/冲突、硬链接及权限；真实手机浏览和编辑仍待加载新版桥后验收。

## 2026-11-21 USB 递票自动配对

- 电脑配对窗口改为先出票后启动：`pairing-control` 确认设备与反向转发后启动桥、生成一次性票据，再通过 `hdc shell aa start --ps address … --ps ticket <64位十六进制票据>` 直接送达手机。
- 手机 `EntryAbility` 解析 `ticket` 启动参数并校验格式；`Index` 页在冷启动或 `onNewWant` 后自动提交配对，成功后写入 HUKS 凭证。已在配对的其他电脑会被切换；票据消费或超时后清除，不残留。
- `aa start` 失败不再阻断配对：窗口改为展示八位码回退提示，用户可手动输入。
- 真机验收（2026-11-21）：新签名 HAP 覆盖安装后，在 Mac 上执行一次配对动作，全程无人输入八位码，桥状态在数秒内变为 `paired=true` 且 `lastSeen` 持续刷新（手机 SSE 在线）。桥为全新启动，旧凭证已随停桥清空，配对成功只能来自递送的一次性票据。
- 自动化测试用模拟 hdc 覆盖：无设备报错、票据随启动参数下发、手机侧消费后单次失效、新票作废旧票、启动失败回退。
