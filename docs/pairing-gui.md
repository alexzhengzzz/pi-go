# 电脑配对窗口（macOS）

从仓库运行 `npm run build:pairing`，生成 `build/Pi Go Pairing.app`。双击即可使用，也可复制到「应用程序」。需要 macOS 14 及以上；构建时需要 Swift 工具链，运行时使用构建电脑上的 Node.js。

1. 同一 Wi-Fi 下选择「局域网扫码」，确认电脑地址，点击「开始配对」。手机 Pi Go 选择「局域网 → 扫码导入」，扫描窗口二维码并点击「配对并连接」。二维码两分钟内有效，使用后隐藏。多网卡时可以选择地址；更换运行中服务地址前须先停止服务。
2. 配对后手机自动展开会话列表，列出当前电脑 Pi 数据目录中的全部有内容会话，包括没有打开标签页的项目历史。目录支持搜索和分页，不再要求逐个共享会话。默认显示未归档记录；「归档」筛选可以查看已归档记录。
3. 在 Pi Desktop 打开已安装 Pi Go 扩展的会话后，运行时自动接入已配对手机；不需要聊天命令或共享按钮。首次使用新版扩展时重新打开会话以加载新版扩展。历史恢复和新建由 Desktop 适配层处理。打开历史会话时先核对原生会话 ID、文件和项目路径；项目尚未登记时自动登记，保留原有信任和工具审批设置。
4. 选择「USB」，开启「插线自动连接」并保持窗口打开。插上一台已允许 USB 调试的鸿蒙手机后，窗口会自动设置 18977 端口转发，并打开手机 Pi Go，通过 USB 递送一次性票据。平时无需点击连接或输入八位码。不开启自动连接时，也可点击「连接手机」。未能打开手机应用时可按窗口提示手动输入八位码。需要本机安装 DevEco Studio，手机已安装支持 USB 递票的 Pi Go。
5. 窗口显示手机在线、已配对或服务停止状态。USB 模式下撤销配对或停止服务会关闭「插线自动连接」。关闭窗口后，已运行的桥接服务继续运行，窗口暂停检测新插入的手机。

升级前已启动旧桥时，在新窗口发起连接会自动更新旧服务，再为手机配对。

在线状态表示最近 15 秒收到已配对手机请求，不代表模型正在运行。窗口显示运行中会话的当前模型，并标记 `pi-go-test` 离线测试模型。窗口不创建额外代理运行时，也不自动发送聊天内容。

本地会话发现使用用户私有目录中的 Unix socket，接入操作在运行时核对会话 ID。只有 GUI 配对启用电脑级目录；旧的逐会话命令入口保持原行为。配对文件和二维码不通过未认证 HTTP 提供。手机仍沿用 TLS 证书与公钥固定、单次票据及加密凭证保存流程。

验证：`npm test` 覆盖真实 Pi RPC 会话发现和自动接入、过期会话拒绝、跨项目历史、超过 250 条目录的搜索/分页、LAN 配对/撤销/停止，以及 USB 递票自动配对（模拟 hdc：票据随 `aa start` 启动参数下发、手机侧消费后单次失效、旧票据随新票据作废、启动失败回退八位码）；原生应用构建和窗口布局已检查。2026-11-21 真机验收通过：插入已允许调试的手机后点击「开始配对」，无需输入八位码即自动完成配对并保持在线。

## Desktop 原生切换支持

构建配套 Desktop：`npm run build:desktop-host -- /path/to/pi-desktop`。源码需要是适配层锁定的 v0.2.2-alpha 检出并已安装依赖。构建会生成带本地服务启用标记的 macOS app，不依赖额外启动环境变量。

退出 Pi Desktop 后执行 `npm run install:desktop-host`，安装脚本先验证签名，把原版应用移入用户私有备份目录，再替换应用；保留现有 GUI 配置和 Pi 数据。重新打开 Desktop 后，已有手机配对可直接使用，无需重启桥或重新扫码。

原生集成测试：`PIGO_DESKTOP_APP="/absolute/path/Pi Desktop.app" node --test test/desktop-host.test.mjs`。测试使用隔离 Pi 数据与 Desktop 配置，经手机同一 HTTP 接口依次打开两个不同项目的历史，再切回第一条，核对目标 ID 和聊天消息；同时确认未自动授予项目的信任权限。
